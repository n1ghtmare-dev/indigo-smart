# Этап 2. Собрали и проверили исходные числа

## Простыми словами

Сделали «полку с оригиналами» и отдельно рабочие таблицы. Оригиналы нужны, чтобы всегда можно было проверить, откуда взялось число. Рабочие таблицы будет читать программа.

## Что выполнено

1. Сохранены копии трёх присланных PDF в `data/original/pdf/`. Файлы из Downloads не менялись.
2. Скачаны 18 материалов организаторов: таблицы, сценарии, правила, контрольные примеры и подборка источников.
3. Зафиксирована версия репозитория `cec6de1950276091689e71a67f9a875fb4ca6213`. Будущие изменения сайта не подменят наш набор.
4. Сохранены SHA-256 всех 21 исходных файлов. Хеш — цифровой отпечаток: если файл изменится, проверка это заметит.
5. Пять CSV скопированы в `data/reference/`. Числа сопоставлены с PDF; контрольные BASE/STRESS представлены также в JSON для нашего будущего кода.

## Где лежат числа

| Что | Файл |
|---|---|
| Спрос по шести годам | `data/reference/demand.csv` |
| Пять каналов | `data/reference/supply_sources.csv` |
| Два режима хранения | `data/reference/storage_options.csv` |
| Три инвестиционные опции | `data/reference/investment_options.csv` |
| Семь строк основных ограничений организатора | `data/reference/constraints.csv` |
| Стандартный и стрессовый сценарии | `configs/scenarios/` |

Семь строк ограничений в CSV не исчерпывают всех правил кейса. Например, материальный баланс, доступность мощностей и отсутствие двойного начисления тоже проверяются отдельно по спецификации.

## Как проверяем

Наш скрипт сверяет неизменность оригиналов, соответствие рабочих CSV оригиналам, ключи и числовые значения, связи таблиц и изменения сценариев. Для важных чисел сохранён независимый контрольный список, вручную сверенный с PDF. Это не автоматическое распознавание PDF.

Скрипт также формирует таблицу входов BASE, STRESS, низкого и высокого спроса. Например, стрессовый общий спрос 2038 года равен 287,5 т, критический — 195,5 т. Это пересчёт условий, а не доказательство обеспеченности топливом.

Запуск: `python3 scripts/verify_preparation.py --write-report`. Читаемый результат: `results/preparation/report.md`; числа по сценариям: `results/preparation/scenario-inputs.csv`.

Фактический результат первого запуска: 40 проверок подготовки пройдены, ошибок нет. Дополнительно пройдены 15 тестов самой проверки, включая намеренно испорченные временные копии данных. Исходники при этом не меняются.

## Что выяснилось

Первичный Excel, упомянутый в постановке, не предоставлен. В README данных организаторы тоже отмечают его отсутствие. Поэтому мы проверили PDF и CSV, но не заявляем сверку с отсутствующим Excel. Ещё одна ссылка организаторов ведёт на `ERRATA_AND_PROVENANCE.md`, которого нет в сохранённом коммите. Оба ограничения записаны в документах происхождения данных.
